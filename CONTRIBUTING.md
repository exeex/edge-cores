# Contributing to edge-cores

File all project issues in the
[edge-cores issue tracker](https://github.com/exeex/edge-cores/issues), even
when the affected code is stored in a submodule. Do not split discussion across
submodule issue trackers.

Fork `exeex/edge-cores`, create a focused branch from current `main`, run the
tests selected for the changed surface, and open a pull request using
`.github/pull_request_template.md`. The maintained workflow is documented in
`.codex/skills/edge-contribution/SKILL.md`.

Unless explicitly stated otherwise, any contribution intentionally submitted
for inclusion in files maintained directly by edge-cores is provided under the
Apache License, Version 2.0 (`Apache-2.0`), without additional terms or
conditions. You must have the right to submit the contribution under those
terms.

Contributions to a submodule are governed by that submodule's license and
contribution rules. In particular, contributions to `src/edge-rv` are provided
under `CERN-OHL-P-2.0`. Submit all resulting integration issues and pull
requests through edge-cores.
