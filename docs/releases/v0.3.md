# v0.3 — Flexible SRAM, native FP4 and PyTorch module compilation

v0.3 rewrites edge-e3's SRAM scheduler to support more data formats and
quantization schemes: **FP8 (E4M3FN/E5M2), FP4 (E2M1), Q8_0, NVFP4 and
MXFP4**. These are implemented in the Tensor weight-loading path and NNC
quantized Linear operators, with runnable public examples for each format.

NNC also adds reusable PyTorch `nn.Module` wrappers and an explicit
`import nnc` / `nnc.compile()` workflow for composing and compiling models.

## Main changes

- **Higher precision accumulation for BF16 inference.** E3 accumulates BF16
  computations with **13 explicit mantissa bits—three more than NVIDIA TF32's 10**
  ([TF32 format](https://developer.nvidia.com/blog/accelerating-ai-training-with-tf32-tensor-cores/)).
  Compared with E3 v0.2's BF16 accumulator, v0.3 preserves small contributions
  across K tiles that were previously lost to BF16 rounding. Public inputs
  and outputs remain BF16.
- **Native hardware decoding, parallel with Tensor MAC.** FP8, FP4, Q8_0,
  NVFP4 and MXFP4 weights and scales are decoded on the fly by dedicated
  hardware. Decoding overlaps Tensor MAC execution, requiring no software
  or vector-instruction decode kernel and adding no separate decode compute
  phase. This reduces weight storage and transfer requirements while keeping
  decoding off the instruction stream. Each format has an NNC Linear module
  and a public example with RTL output checking.
- **Flexible quantization groups and scale formats.** Different quantization
  schemes need different group sizes and scales. The rewritten SRAM scheduler
  and shared weight/scale loader support these variations in one path,
  including native MXFP4 and NVFP4 byte scales. Existing WLD and SLD software
  operations remain available.

## NNC: compose models, then compile

The new `nn.Module` wrappers let users compose supported models in familiar
PyTorch code. Wrap ordinary `torch.nn.Linear` layers with `LinearFp4`,
`LinearMxFp4`, `LinearNvFp4`, `LinearQ8_0` or the FP8 variants, then call
`nnc.compile()` to generate C++ and packed weights. The
[Llama 3 example](../../example/llama/README.md) now uses this module API
throughout its transformer-block graph. See the [README demo](../../README.md#pytorch-to-asic-rtl-with-nnc).

The next step is user-defined quantization strategies that feed NNC's
supported ops. Current wrappers use preset quantizers; constructors accepting
already user-quantized Linear weights/scales are not yet implemented.

## Q8_0 support

Q8_0 support preserves native FP16 scales and signed INT8 codes, allowing
extracted quantized weights to be repacked for E3 without changing their
encoding. The hardware uses E3 tile order, so row blocks still need repacking;
a GGUF file importer is not included. See the
[public Q8_0 contract](../../src/edge-nnc/QUANT_LINEAR.md).

## Development workflow

`scripts/setup-python.sh` installs PyTorch and editable NNC from `src/edge-nnc`
into the project environment, so local compiler/runtime edits take effect
without reinstalling. Use `.venv/bin/python` or activate that environment.
The root `nnc` symlink is removed; scripts use `src/edge-nnc` directly.

## Validation and compatibility

Public examples and regressions verify numerical results, packed formats,
scale changes and circular-buffer wrap. The
[validation audit](v0.3-validation.md) records commands and outcomes; the
[performance snapshot](v0.3-performance.md) records current Tensor/ACTU cycles.
Validation covers E3 RTL simulation and excludes private `test-e3`, E4 and
silicon measurements.

Rebuild software using the previous intermediate P/O layout.
NVFP4 currently rounds its per-tensor global scale to BF16. Format support
does not imply bit-identical accumulation with GPU or llama.cpp kernels.
For implementation details, see the
[SDK manual](../../src/edge-e3/include/README.md),
[packed weight tutorial](../tensor-packed-wsld.md), and
[native FP4 contract](../../src/edge-nnc/MICROSCALE_LINEAR.md).
