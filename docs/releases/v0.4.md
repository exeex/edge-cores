# v0.4 — Edge32 at 1 GHz and JTAG debugging

Draft release notes, prepared 2026-11-18.

v0.4 focuses on the physical implementation of Edge32 and an interactive
scalar-debug workflow. More than a hundred APR experiments helped identify
routing bottlenecks and long combinational paths. Registering selected control
and data boundaries, localizing completion ownership, and restructuring cache
interfaces bring the current RV32 integer core/cache integration to **1 GHz
on ASAP7**, with positive setup and hold slack in the latest global-route run.

## Timing-driven pipeline and cache changes

The IF/ID/EX/WB pipeline keeps architectural execution in order while shortening
physical paths. Changes include earlier operand-index selection, separating ID
payload capture from late transaction qualification, local MUL completion,
registered AXI requests and refill responses, and synchronous reset boundaries.
Cache metadata and bank reservation no longer carry unnecessary reset/error
qualification through long selection paths. The D-cache separates refill bank
reservation from byte commit, so failed beats suppress writes without extending
the arbitration path.

The latest full-core/cache/native-debug measurement uses a 1,000 ps clock:

| Block / checkpoint | Measurement stage | Setup slack | Hold slack | Independent DRC |
| --- | --- | ---: | ---: | --- |
| RV32 integer core + caches + native debug | Global route | +163.14 ps | +20.03 ps, all paths | Full-core detailed-route result not established by this run |
| I-cache | Detailed route + RC extraction | +204.63 ps | +58.59 ps, internal registers | 0 |
| D-cache | Detailed route + RC extraction | +264.41 ps | +36.97 ps, internal registers | 0 |

The full-core result has zero setup/hold TNS, zero overflow and no unconstrained
paths. Cache standalone all-path hold is −188.80 ps (I-cache) and −206.38 ps
(D-cache); their external boundary hold is owned by the containing design.
These are ASAP7/OpenROAD implementation results, not fabricated-silicon
measurements or foundry DRC/LVS signoff. The full-core global-route result does
not imply full-core detailed-route closure.

## Three-cycle integer multiplication and the FPU boundary

The multiplier now uses a shared signed 33×33 datapath, with operand extension
covering MUL, MULH, MULHSU and MULHU. The selected ASIC strategy combines Booth
mapping, sequential retiming and physical placement with EX-local completion.
The result is available on the **third capture edge** (two full clock intervals
after the acceptance edge), the three-cycle MUL interface contract.
This reduces the multiplication dependency in index/address calculations;
no new end-to-end application speedup is claimed here.

The physical partition moves the FPU away from the integer critical region.
The external FPU interface adds **one ingress capture cycle** before FP compute,
FP load/store or FP CSR execution; completion is also registered. Integer
instructions do not incur that FP ingress cycle. **FPU state is not yet included
in the debug interface, and FPU APR integration is not part of this release.**
Both are future work. See the [Edge32 architecture](../../src/edge-32/README.md).

## Native debug interface and JTAG adapter

The native request/response debug interface supports acknowledged halt/resume,
single-instruction step, halted PC and GPR access, and cache maintenance.
The JTAG adapter adds a JTAG DTM, DMI debug module, system-bus access for loading
and inspecting memory, and a console FIFO. Debug memory access coordinates with
halt and cache maintenance so downloaded code and scalar data stay coherent.
The external JTAG/DMI transport is outside the native-core APR boundary.

The new [jtag-hello example](../../examples/jtag-hello/README.md) demonstrates
VS Code's debugger GUI using cppdbg → RISC-V GDB → OpenOCD → JTAG RTL. F5 builds
and starts the session; source breakpoints, stepping, Watch and the console
work through the debug path. Stopping the session shuts down its services.
Program bytes are downloaded over JTAG, with no simulator preload.

The example builds directly from the public Edge32 RTL and versioned local
simulation support. It needs no private repository or prepared APR views. It is
an optional workflow, separate from the public software regression. FPU debug
and standard GDB hardware-breakpoint integration remain future work.

## Validation

The current workspace software regression passed: 49 NNC unit tests, all 61
model/profile cases, 26 packed configurations, 16 weight-packing configurations,
cache ownership, six Matmul interface cases, and all 11 public examples.
The migrated JTAG example additionally exercises the real cppdbg/GDB/OpenOCD
path, console delivery, service cleanup and restart.

See [v0.4 validation](v0.4-validation.md) for source versions, commands, evidence
and the limits of GUI and physical verification. No release tag or GitHub
