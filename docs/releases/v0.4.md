# v0.4 — Edge32 at 1 GHz and JTAG debugging

v0.4 brings Edge32 to **1 GHz on ASAP7** in the current integer core/cache
global-route results, and adds a public **JTAG debugging workflow** with
VS Code, GDB and OpenOCD.

More than a hundred APR experiments helped identify routing bottlenecks and
overly deep combinational logic. The resulting pipeline and placement changes
shorten critical paths while preserving in-order execution.

## Main changes

- **Pipeline and cache changes for 1 GHz.** Registering long control and data
  paths, localizing completion logic and restructuring cache interfaces improve
  timing across the integer core and caches. The latest core/cache/native-debug
  global-route run reaches **+163 ps setup slack** at a 1,000 ps clock, with
  positive hold slack. I-cache and D-cache have also completed detailed routing
  and extraction with zero independent DRC violations within their leaf contracts.
- **Three-cycle integer multiplication.** Revised multiplier mapping, retiming
  and placement shorten MUL latency to three cycles, helping dependent index
  and address calculations. The physical partition moves the FPU farther from
  the integer critical region, adding one ingress cycle to its interface.
- **Native debug interface and JTAG adapter.** Edge32 now supports halt/resume,
  single-step, PC and register access, and coherent debug memory access. The
  JTAG adapter provides program download, memory inspection and a console over
  the same debug connection.

## Debug with VS Code

The new [jtag-hello example](../../examples/jtag-hello/README.md) connects
VS Code's debugger GUI to the simulated core through GDB and OpenOCD. Use F5
to build and launch, set source breakpoints, step through code and inspect
variables with Watch. Program bytes are downloaded over JTAG, and stopping
the debugger shuts down the session's services.

The example builds entirely from public RTL and local simulation support;
no private test repository or prepared APR views are required.

## Physical implementation status

| Scope | Status |
| --- | --- |
| RV32IM | Detailed-route checkpoints completed; independent DRC cleanup remains. |
| I-cache and D-cache | Detailed routing and extraction completed; independent DRC 0. |
| DTCM / SRAM, tensor dot unit and ACTU | Partially completed. |
| CMPU and complete E3 ASIC assembly | Not yet completed. |

The 1 GHz core/cache result is from global routing; full-core detailed-route
closure remains open. **FPU debug support and FPU APR integration are deferred.**

## Validation

The full public software harness and JTAG regression passed in a clean checkout.
The actual VS Code GUI workflow was also verified, including breakpoints,
stepping, Watch, session cleanup and restart.

The [validation record](v0.4-validation.md) contains component revisions,
test results and detailed APR measurements. Physical results use the recorded
APR source revision; the new public debug integration was functionally tested
but not rerouted. Board-level JTAG and standard GDB hardware breakpoints remain
outside this release's validation.
