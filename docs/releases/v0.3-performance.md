## Tensor

The [public source](../../example/tensor/matmul64x64_128tokens_tiled_circular.cpp)
uses BF16 input/output and packed INT8 identity weights, with 64 tile starts
and 128 token steps per start. The old README called this a BF16 matmul;
the updated snapshot explicitly states the weight format.

```text
cycle_start=458996 cycle_end=467634 cycle_delta=8638 starts=64 setn=128
EDGE_DEMO TEST PASS cycle=477151
```

Ideal MAC cycles are `64*64*128 / (8*8) = 8192`.
Effective MAC utilization is `8192/8638 = 94.84%`.
The interval begins before packed weight DMA, includes circular transposed
weight loading and Tensor loop/control overhead, and ends after Tensor/DMA
synchronization. Test-data initialization and the final output copy to DRAM
are excluded. This identity-weight fixture is a throughput/transport check,
not a model-quality or arbitrary-quantized-GEMM throughput claim.

## Activation

The [public source](../../example/actu/actu_throughput.cpp) measures 4,096 BF16
elements. Each kernel is warmed once at the same address, then timed on its
second run. Each measured segment starts before command `start` and ends
after `sync`. Input preparation, setup before each segment and output
validation are excluded.

```text
elements=4096 sigmoid_cycles=4143 silu_cycles=4149 tanh_cycles=4149 softmax_cycles=12413
EDGE_DEMO TEST PASS cycle=832583
```

| Kernel | Ideal stream cycles | Measured cycles | Effective stream utilization |
| --- | ---: | ---: | ---: |
| Sigmoid | 4,096 | 4,143 | 98.87% |
| SiLU | 4,096 | 4,149 | 98.72% |
| Tanh | 4,096 | 4,149 | 98.72% |
| Softmax | 12,288 | 12,413 | 98.99% |

Ideal stream cycles assume one element per cycle per pass. Softmax sums
three separately timed passes: CMPU maximum, ACTU exponent/sum, and ACTU
normalization. Inter-pass scalar setup is outside these intervals, so this
is not the complete Softmax function's wall-clock interval. These ratios
describe effective command-level stream throughput, not instrumented
internal pipeline busy cycles. The fixture uses all-zero inputs and checks
all output elements; broader numerical coverage belongs to the NNC suite.
