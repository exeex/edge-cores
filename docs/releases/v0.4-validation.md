## JTAG example

The original example was migrated from `n906/examples/jtag-hello`. Unlike its
original prebuilt-simulator dependency, this version builds its own simulator
against the maintained native debug req/resp boundary and synchronous reset
bridge. The prepared mainline RTL was imported from the physical workspace's
`build/apr-mainline-debug/edge32_full_core_debug_rtl`, checking producer output
hashes. This import is an explicit private artifact prerequisite, not a claim
that the public checkout independently regenerates the APR views.

```sh
python3 examples/jtag-hello/debug.py import-views \
  /path/to/physical-workspace/build/apr-mainline-debug/edge32_full_core_debug_rtl
./examples/jtag-hello/run.sh
```

Tools: Verilator 5.050, OpenOCD 0.12.0, RISC-V GDB 18.1, LLVM clang/LLD and
VS Code Microsoft C/C++ 1.35.6 on macOS ARM64.
The DAP client uses the checked-in launch configuration with workspace paths
expanded, selects the local GDB, and runs the task lifecycle explicitly.

Checks: ELF download through OpenOCD/JTAG SBA; stop at `main`; C source
breakpoint; stack trace; Watch of `message`; disassembly; source step;
completion with `characters_written == 25`; exact console greeting; disconnect;
cleanup of all owned processes; released TCP ports/control socket; repeated
stop; fresh start/stop. Local logs and the final PASS marker live under
`build/jtag-hello/`: `test.report`, `dap-check.log`, `session.log`, `restart.log`,
`sim/build.log`, `views-import.json` and the producer receipts in `views/`.

The real cppdbg adapter was exercised over DAP. The VS Code GUI/task UI was
not driven automatically. FPU registers/operations, hardware-board JTAG,
standard GDB hardware breakpoints and physical JTAG timing are not validated
by this example. No RTL source or existing regression expectations were changed.
